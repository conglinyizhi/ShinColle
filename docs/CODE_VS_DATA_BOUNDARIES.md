# ShinColle Code vs Data Boundaries

本文档用于回答迁移阶段一个经常反复出现的问题：

> 哪些内容应该继续保留在代码里，哪些内容适合逐步迁移为数据定义？

这份清单不是重构指令，而是边界说明。它的作用是避免后续在做 `datagen / datapack / 配置拆分 / 注册表拆分` 时，把依赖运行时语义的逻辑误下沉为静态资源。

## 一、必须继续保留代码实现的逻辑

以下内容当前明显依赖运行时状态、服务端判定、复杂回退或跨系统联动，不适合直接改成纯数据定义：

### 1. `ShipyardRecipes` 的建造选择算法

虽然候选表本身看起来像数据，但以下部分仍然属于代码语义：

- 小船坞 / 大船坞分支切换
- 候选均值与偏好材料的概率分布计算
- 缺省材料与回退输出
- 建造结果到 spawn egg / 装备物品的解析逻辑

结论：

- `候选表` 将来可以进一步抽成数据。
- `概率计算 / 回退守卫 / 结果解析` 仍应保留在代码。

### 2. `LegacyEquipStats` 与装备属性计算

当前装备系统不只是“配置表”，而是以下三层共同组成：

- 装备变体 ID 与显示映射
- tooltip 展示与创造栏排序
- 真正参与战斗计算的属性数组与特殊效果

结论：

- 纯静态数值表未来可评估外置。
- 与 `LegacyEquipItem`、JEI、tooltip、附魔表现耦合的部分仍应保留代码控制。

### 3. `TaskHelper` 自动化任务逻辑

以下逻辑不适合直接数据化：

- fishing / mining / cooking / crafting 的运行时入口
- 容器侧面、路径点、物品消耗、掉落生成
- 旧版兼容 fallback 语义
- 任务失败恢复与输入输出路由

结论：

- 掉落表、采矿候选或静态映射可以逐步表驱动。
- 任务生命周期与状态机仍应保留代码。

### 4. `HostileSpawnManager`

敌对生成不仅依赖数值，还依赖：

- 玩家状态与时间条件
- 位置合法性与碰撞守卫
- 真实生成数量与广播条件
- hostile 初始化与 boss 扩展后处理

结论：

- 刷新参数可继续暴露配置。
- 生成控制流和安全守卫必须保留在代码。

### 5. `EntityShipBase` / AI / 战斗联动

以下是典型“不能误判成数据驱动”的区域：

- Brain AI 状态切换
- 跟随 / 守卫 / 巡航 / 编队恢复
- 攻击前置检查、资源消耗、召唤物生命周期
- 婚后状态、骑乘、合体与被动反应

结论：

- 这是迁移的核心行为语义，当前不属于 datapack 化目标。

## 二、适合逐步抽成数据定义的内容

以下内容已有明显表驱动特征，适合在不破坏主逻辑的前提下逐步下沉：

### 1. 配方、标签、worldgen、loot

这些内容已经主要落在资源目录中，后续重点是：

- 用 datagen 减少手写 JSON
- 统一生成规则，降低漏改概率

### 2. Patchouli 目录骨架与统一模板

手册正文仍然偏手工，但以下部分适合先模板化：

- category / entry 索引骨架
- 一致格式的 recipe 页
- 一致格式的 image 页 / spotlight 页

### 3. 批量可预测的语言键

例如：

- spawn egg 命名
- 成组成套 tooltip key
- 固定模式的 JEI / Patchouli 说明键

这类内容适合后续通过脚本或 datagen 生成，但不影响核心逻辑代码。

## 三、适合“代码 + 数据”混合治理的内容

这些模块不适合二选一，应该按“表定义外置、控制流保留代码”处理：

- `ShipyardRecipes`
- `LegacyEquipStats`
- 敌对生成候选
- 自动化任务的静态掉落候选
- JEI 配方展示映射

建议做法：

1. 先抽出纯静态候选表。
2. 保留运行时验证、回退守卫和对象解析在代码层。
3. 每次抽离后补防回退测试，确认语义没漂移。

## 四、当前阶段的推荐边界

如果继续推进迁移，建议遵守以下边界：

- `data/` 与 `assets/` 目录：优先承载静态资源与可预测表。
- `init/`、`event/`、`server/`、`entity/`、`utility/`：继续承载运行时逻辑与安全守卫。
- 文档和回归测试应先于大规模数据化重构落地，避免在没有边界说明的情况下盲目拆表。

## 五、当前结论

- 资源不等于语义，能写成 JSON 的内容不一定就应该完全脱离代码。
- 当前最稳妥的方向是：继续资源化静态表，保留控制流与兼容语义在代码里。
- 后续在推进 `舰娘模板 / 装备参数 / 声音覆盖规则` 等数据化候选时，应优先参考本文档与 `DATAPACK_CANDIDATES.md`。
